# TNI Rater Autofill

A Chrome extension that reads a client's **TNI Commercial Insurance Quote Application** (the fillable PDF) and fills Progressive, AmWINS, and GEICO rater fields from it. Optional AI assistance from OpenAI GPT-6 Luna helps choose among the carrier's existing radio, select and checkbox options when the rules leave a choice unresolved.

The extension fills supported fields, reports unresolved questions, and preserves agent corrections. It can use carrier-specific Continue or Save & Continue actions when enabled and no review blockers remain; it never binds, buys, or submits the application. Some carrier defaults replace prefilled choices, so review the result.

For development, [AGENTS.md](AGENTS.md) and [CLAUDE.md](CLAUDE.md) contain the same short guidance. Use their task-specific links only when changing the corresponding system. The [architecture guide](docs/architecture.md) distinguishes implemented behavior from the project's remaining goals.

Starting on a new Windows computer: follow [Windows development](docs/windows-development.md).
The [development handoff](docs/handoff-2026-10-09.md) records the merged audit work and remaining limitations.

## Install

Agents install it from its private Chrome Web Store listing (see [docs/chrome-web-store.md](docs/chrome-web-store.md)). For development:

1. Run `npm ci` once, then `npm run package`. Open `chrome://extensions` and turn on **Developer mode** (top right).
2. Click **Load unpacked** and pick `dist/tni-rater-autofill`. That copy has a fixed extension ID (`cbpjccegchfackokbiogplhdekblkccj`), so its settings, including the OpenAI key, survive removing and loading it again.
3. Pin the extension, then click its icon to open the side panel.
4. After the next `npm run package`, click the extension's reload button. Open carrier pages need no refresh: the fill scripts left in them are replaced on the next fill (each build is stamped), and the usage recorder when the panel next follows the tab. Reopen the side panel to get its new version. The side panel is built with Vite: for panel edits only, `npm run panel` (or `npm run panel:watch`) rebuilds it in that copy without packaging again.
5. Open **Settings** (the gear at the top of the panel) and enter your initials under **You**. For a practice or test quote, open **Settings → Advanced, for setup only** and tick **This intake is a test run, not a client** (shown while an intake is loaded; agents don't see it unless they open Advanced): the weekly review leaves it out of its numbers (the PDF is remembered on this computer). **Server** defaults to TNI's central collection server. For local development, set it to `http://localhost:8787` and start `npm run server`.

## Using it

1. Drop the client's intake PDF into the side panel. The top of the panel names the rater page you're on (the carrier, the quote step and, for Progressive, AmWINS and GEICO, "Step 3 of 7" with a progress bar); under the client come three steps, **Intake**, **Fill page** and **Review page**, each a click away; the last two are about the page in front (each page is filled and reviewed in turn; the header's "Step 3 of 7" is the quote's place). The bar at the bottom of the panel always says the one next thing to do, with its button (Fill this page, Stop, Show the next one, Approve, Looks right, continue, or Continue once nothing on the page is left for you, also once you've answered the last item yourself: a fill that replaces nothing and clicks the page's Continue; with only buttons left to click, Continue clicks the ones it can in turn and the page's Continue once none is left, or **Click them for me** where Continue is yours or with **Let me look first** on, which then asks for Looks right).
2. **Intake**: things the form got wrong or left ambiguous, such as an address with no commas, a VIN that fails its check digit, answers typed into the claims box, a radius given as a range or in kilometres, or a missing or unclear vehicle ownership answer. Fix the value in its card if needed, then **Looks right**; **See intake** (**See intake, page 2** on an intake of several pages) opens the intake PDF in a sheet over the panel with that answer outlined, at 200%; **Intake** next to the client's name opens the whole PDF at the panel's width. Drag the page to move around it; the buttons or Ctrl + wheel zoom. **All client details** (the row under the checks, or the client's name at the top of the panel) opens every answer on the intake in a drawer from the right, to read or correct, by section (each folds); fields the intake leaves blank are hidden unless flagged or edited by you, behind **Show N empty fields**. Your edits are what gets filled. You can fill pages before you finish.
3. **Fill page**: open the rater page and click **Fill this page**. If the client has several drivers or vehicles, pick which one the current page is about first (the lists at the top of the page's answers; they show only on a page about one driver, vehicle or trailer, and never on AmWINS, which fills them all at once). If the quote on the rater is for another state than the intake's garaging state, the panel says so and fills nothing until you click **<state> is right** or **Fill anyway**. On GEICO, with **Fill the pages** or **Continue when the page is done** on, the fill adds each intake vehicle, trailer and driver not on the quote yet by itself (the list's +, Vehicle or Trailer on the chooser and its Next), once each, and fills the form that opens for that one; with both off you click + and the chooser's Next yourself and the fill picks Vehicle or Trailer; with it on, a chooser you open yourself is answered and continued too. The fill clicks + only once the page has been quiet for a second, once, and waits for GEICO's chooser (up to 20 s after the page is quiet) instead of clicking again. A button you click yourself while a fill runs (Next, +, Looks Good) is that step's move: the fill clicks nothing more on it. On GEICO a Next that doesn't move the step is never clicked again: the page may load for up to a minute, and you are told after about 18 s of a quiet, unchanged page. A unit the list can't tell apart (no VIN, or a driver's name another driver's name holds) isn't added while the list shows a row the extension can't account for: add it yourself if it isn't there. With the setting on, the fill also clicks Next (Save and Continue on Add Driver) on each step and form up to Additional Business Info once nothing on it is left for you, each form once, and Looks Good once the list shows every intake unit; on Quote & Coverages and after it, Next is yours. A form that may be another one's than the one picked (the picked one was filled on an earlier form) is held, with nothing typed in it, until you pick the one it is about and fill again; one filled for another says which, so you pick that one and fill again, or correct its answers yourself if it is the picked one's; what you answered on it yourself stays. GEICO's Final Quote Details, MVR & CLUE and Payment Information are yours: nothing is filled or clicked there. While it fills, the bar counts the answers in and the list shows each one as the page takes it. If the page stops answering for a few seconds (a message box open on it), the bar says so: answer the box on the page and the fill goes on. A page that changed before the fill began isn't filled with the earlier page's answers; fill the page in front. With something open over Continue or a button the fill clicks (a dialog, a message, a chat window), the fill doesn't click through it and says which button: close it and fill again. **Stop** halts it after the answer going in, keeps what's in, and clicks nothing more (Continue included). **Answers on this page** then lists every answer and every question left for you, in the order of the page. An answer from the intake has no tag; the others say where they came from: **Worked out** from intake answers (the owner's full name, a phone number without its punctuation), **Your edit** (an answer you set or corrected in the panel, such as a driver's gender), **TNI standard**, **On the page**, **Clicked**, and **You** (fields you answered on the page). The **i** next to the list's title explains the tags and the marks on the rater page. Click an answer to see its source (for an intake answer, its PDF page): **See in intake** shows where it came from on the PDF (for a worked-out answer, the answers it was worked out from; a TNI standard has none), and **Change answer** shows the choices the page offers for a list, radio or checkbox and puts the one you pick in for you (it is then yours, and no fill changes it); for a typed answer it scrolls the rater page to the question for you to change there. **All**, **Need you** and **Filled** narrow the list. Once more than one page is filled on the quote tab, **This page ▾** next to the title lists the earlier ones: pick one to read its answers as they were filled (view only; change them on that page), and **‹ This page** goes back. The panel keeps them while it is open. Opening Review page or Filled reads the page again and marks any answer the page shows differently now, with what it shows.
   - If the intake's current commercial auto insurance is with the carrier you're on (GEICO or Progressive, also misspelled, such as "Gieco" or "Progresive"), a red card at the top of the page's answers says so as soon as the carrier's page opens: the carrier may decline or route the quote, so check with the client. The **Intake** step says it first, in red at the top of its checks, naming the carrier. It doesn't stop filling.
4. **Review page**: what's left for you on the page, AI picks to approve, and what happens about Continue. Where the quote ends on the rater (GEICO: Print Quote Proposal clicked on Quote & Coverages with nothing left for you; Progressive: Print, Email, Fax clicked on Rates, after which the print page is yours; AmWINS: a fill on Underwriting that leaves you only the declaration), the step says **Quote done** and the bar says what was clicked (on AmWINS: tick the declaration, then click Submit, both yours; neither is ever done for you); on GEICO and Progressive, once anything on that step changes afterwards (on the page, a pick in the panel, an AI pick, or a fill that puts an answer in) it isn't, since the printed proposal is no longer the quote on the page, until it is clicked again (on GEICO, Print Quote Proposal by you after your Recalculate). A fill that stopped short isn't Quote done either. The count goes down as you answer items on the page; **Show the next one** in the bar opens the next. A question you can answer in the panel (a choice the page offers) shows its choices: the one you pick goes in on the page, marked as yours, and no fill changes it. Report orders, exclusions, signatures, payment questions, typed answers, and anything on a step that is yours are answered on the rater page. **Show on page** scrolls the rater page to an item's question and flashes its mark (nothing is changed or clicked). **Mark done** settles an item you've answered or want left as the page has it: the panel won't fill it or wait on it on this page, nothing is clicked, and **Undo** gives it back. Each tab and page keeps its own report, so switching to another quote tab and back shows it again (with the time of that fill), and so does closing the panel and opening it again (until Chrome is closed). Look at the marks on the page (the **i** next to the list's title shows the same colors):
   - **green**: filled from the intake, or worked out from it
   - **blue**: filled with a TNI standard answer, an assumption rather than a fact from the intake (for example gender MALE, None of the above, or year licensed from the birth year), tagged **TNI standard** in Answers on this page. A standard you have to confirm (review mode) is amber dashed instead.
   - **amber dashed**: needs you (not on the intake, or required by the rater)
   - **red dashed**: couldn't fill (for example, no dropdown option matched). The side panel lists the options it saw.
   - **slate**: your pick, put in from the panel's choices (Change answer, or a question's choices on Review page)
5. Review unresolved questions and AI selections. With automatic continuation enabled, supported pages advance once blockers are resolved; otherwise continue manually (on GEICO, from Quote & Coverages on, always: you click Next there and on every step after it). If the rater changes an answer the extension filled while it waits to click Continue, that answer moves to **Couldn't fill** and Continue isn't clicked.
6. **Let me look first** (Settings → Filling, on by default, with **Continue when the page is done** on): when a page is done, the panel reads its answers back and Continue waits for **Looks right, continue** in the bar. Looks right continues the page only as you saw it: if anything on the page changed after you clicked it, the page is held again ("The page changed"). The switch is kept on this computer and isn't in the usage log.
7. **Sound when the quote is done** (Settings → Filling, on by default): a short notification sound when the rater's last step is clicked on a quote (GEICO's Print Quote Proposal, Progressive's Print, Email, Fax; a Progressive NTL quote that also asks for cargo or general liability, whose Rates page is yours, doesn't count it), by you or by the fill, the fill's click only when nothing on that step is left for you. It sounds once a print: again after something on that step changes and it is printed again, and for a new quote (New quote with this intake), not for the same quote printed again. On AmWINS it sounds once a quote, when a fill on Underwriting leaves you only the declaration: also the fill that follows your answer there (with **Fill follow-up questions** on) or **Fill this page again**, not **Mark done** alone. Chrome plays it once you have clicked in the panel at least once. The switch is kept on this computer and isn't in the usage log.
8. **Open in its own window** (the square with an arrow at the top of the panel, next to Settings) moves the panel out of Chrome's side panel into a window of its own, which you can drag anywhere, such as another monitor, so the quote tab keeps the whole browser window. It opens where you last left it, at the size you left it. It works on the tab in front in the Chrome window you used last, as the side panel does in its own window, and keeps the quote tab while you look at another site. Only one copy of the panel runs then: the side panel closes as the window opens, and the side panel opened again (**Back to the side panel** at the top of the window, or the extension's icon) closes the window. Neither button works while answers are going in: it says to wait. The new copy shows each quote tab's earlier reports again, with the time of their fill. The intake, your edits and settings carry over, and so does what the old copy knew of each quote tab (its step, a screen that is yours). Chrome doesn't keep the window above others, and it slows a page whose window is minimized or fully covered, so keep the quote in view while it fills.

### AI assistant

**Suggest answers** is on from the start, and no key is needed: Luna goes through TNI's usage server, which adds TNI's OpenAI key (`OPENAI_API_KEY` on Railway, [hosting](docs/hosting.md)). To turn it off, or to use your own key, open **Settings** (the gear at the top of the side panel) and open **AI**. **Use my own key** takes your **OpenAI API key** (**Save** or Enter); it stays in this device's extension settings, goes straight to OpenAI, and is never included in usage logs. Luna uses the fixed `gpt-6-luna` model.

The rules run first. Luna receives unresolved choice questions, the carrier's actual options, active driver/vehicle context, intake facts and carrier-scoped TNI rules. It proposes a visible option or leaves it for the agent. Luna can explain a suggestion, but it never types names, identifiers, dates, amounts or other free-text answers.

A suggestion shows in its question's row: **Use this answer** applies it (marked **purple**); **No thanks** dismisses it. Cited sources must exist and a second Luna call checks evidence support. This does not prove correctness. Ambiguous or unsupported choices stay unresolved. Report orders, exclusions, signatures, payment/billing fields and typed identifiers are agent-owned. **Put checked picks in** is separately opt-in and requires Luna's evidence check. Automatic picks block Continue until you approve them, in their rows or with **Approve** in the bar; rejecting one keeps the hold until you change the field or explicitly confirm its current answer. Pending holds survive panel reloads. Saved choices from a retired assistant remain holds for manual review. Architecture, limits and evaluation scaffold: [docs/ai-assistant.md](docs/ai-assistant.md).

Luna's policy v5 request budget is optimized for bounded review: `gpt-6-luna` uses low reasoning, low text verbosity, up to 12 eligible fields per adaptive request, a 4,096-token choice response cap, and a 2,048-token verification cap. The combined request state and schema stays under 48,000 characters while preserving the complete evidence set needed for the decision. The first call carries the complete fact/rule sources once; the verification call carries the scoped intake and cited evidence. The same local answer cache is used, with no extended paid API cache configuration. These are request-budget limits, not a claim about actual billed tokens, live latency, or live accuracy.

The loaded intake record, and the intake PDF itself (up to 4 MB, for the panel's PDF view), are kept in Chrome's session storage and cleared when Chrome closes or you click **Clear this client** (the trash button next to the client's name; it asks first). **Change file** (the file button) asks first once you've corrected or checked anything; loading the same PDF again keeps your corrections and checks, and a different one starts over. **New quote with this intake** (the restart button; it asks first) is for quoting the same client on the next carrier, or again: this quote's fills, page marks and clicks (vehicles added, Continue) are forgotten, so a page reached again doesn't show the earlier quote's answers, and the intake with your corrections and checks stays. Filled answers go into the carrier's website. With assistance on, unresolved questions and their option texts, relevant TNI rules and the active intake facts are sent to OpenAI with your key. Identifier fields are removed and the client's names, dates of birth, street, city, ZIP, contact and ID numbers are replaced by `[client]` where they appear as written in the intake's fields, in the claims box and notes too (written another way there, such as 1/2/1980 for 01/02/1980, they may still be sent); the garaging state, business class and operations answers, coverage choices, vehicle details, the driver's license state and CDL, and the prior carrier still go in clear ([docs/ai-assistant.md](docs/ai-assistant.md) lists them). One exception to the name redaction: so Luna can flag a driver whose gender may not be the standard Male, drivers' first names (the first word only) are sent on their own in a separate request, with no last name, date of birth or other intake data. Separately, redacted usage events are queued locally and uploaded to TNI's server.

## Setting up a carrier: page captures

Until a carrier has exact mappings, the extension matches fields by their labels ("Date of Birth", "USDOT #", …) using the generic rules in `src/rules.js` (Progressive and GEICO turn them off: `useGenericRules: false`). To make a carrier exact:

1. Load the client's intake (required: its names and numbers are what get redacted), open a rater page, and under **Settings → Advanced, for setup only** give the series a **Scenario** name (e.g. "FL van, hazmat"), then click **Capture page layout**, or press **Alt+Shift+C** with the side panel open (handy with a dropdown list open).
2. Each capture saves a JSON file to Downloads, numbered within its scenario (`capture-<carrier>-<scenario>-<quote>-001-<page>.json`). It lists every field's label, id/name, type, dropdown options and section, which choice is picked, the messages on screen, any open dropdown list, and which intake field the rules would put there (the carrier's, plus the generic ones where it keeps them) (`wouldFill`), with the page, step and view, and the **Note** you typed for it ("set hazmat to Yes"). It contains **no typed values**, and client names and numbers are replaced with `[client]`. Nothing is uploaded.
3. For a follow-up question, capture, change the answer, capture again. Move the files to `layouts/` (kept out of git) and run `npm run captures` (also part of `npm run review`): `reviews/captures-<date>.md` lists each scenario in order with what changed since the last capture of the same page, view and intake. An open list keeps its choices only when it's a fixed list of a known question; a lookup filled from what was typed (an address, a business) keeps none. Do this for every page of the quote flow, and the mappings go into `src/carriers/<carrier>.js`.
4. In an unpacked build, the same section also has **Developer recording**: on the quoting page itself (it records only the tab it starts on), **Record this quote**, do the quote, then **Stop and save**. The recording is one zip in Downloads with every click, key and page change and its time (never typed text); **Note** adds the Note box to it. `npm run recording -- <zip>` tells it step by step ([developer recording](docs/developer-recording.md)).

- Variants: other states (CA, NY, NJ, FL, TX have their own questions), trailer types other than Flatbed, Dry Van and Reefer, hazmat, filings = Yes, ELD = Yes, several drivers/vehicles, box truck / tractor.

## Usage log (pilot)

While an intake is loaded, the extension records how it's used on Progressive, AmWINS and GEICO quote pages, so the mappings can be improved from real quotes. A "Recording usage" label shows in the side panel header, and the **Usage log** section at the bottom of the panel explains it to agents. **Tell agents in writing before rollout** (several states require notice of electronic monitoring of employees).

What's recorded (`src/usage.js`, `src/content/recorder.js`):

| Event | Contents |
| --- | --- |
| `intake_loaded` | intake fingerprint (SHA-256 of the PDF), form version, state, business class, vehicle types, driver/vehicle/trailer counts, requested coverages, warning codes |
| `warning_checked`, `intake_edit` | which warning (code) the agent checked off; which intake field they corrected in the panel (added/changed/cleared) |
| `fill_run`, `fill_field`, `fill_error` | per fill: carrier, page, what was filled/kept/failed and why; chosen dropdown/radio options (not typed text); the fill's run id, the rule files' fingerprint and the filling switches in force; on AmWINS and GEICO the step (AmWINS' heading, GEICO's progress bar). A fill that failed, whose intake changed meanwhile, or whose Continue didn't take: the reason, client names redacted |
| `field_change` | a field that changed on the rater page, by the agent or by the page: for dropdowns/radios the from/to option; for text boxes only whether it matches what autofill typed (same / format / different) and which intake field the new value equals, e.g. `drivers[0].dob`, worked out on the agent's computer; on AmWINS and GEICO the step (AmWINS' heading, GEICO's progress bar) |
| `page_view` | carrier page switches (for time per page) |
| `intake_profile` | a profile of the client's business when the intake is loaded or corrected: state, business class, years, operations answers, each vehicle's and trailer's type, year, make, model and value, each driver's age (not the date of birth), licence state, CDL, marital status and gender, coverages and limits asked for, the current insurer and the month its policy ends; whether a USDOT, MC or FEIN was given, never the number. No names, numbers or addresses; text answers lose anything that looks like an identifier (`intakeProfile` in `src/usage.js`). The client's email and phone go with it only for the server to turn into match codes with `MATCH_KEY`; the server stores the codes, never the values |
| `quote_premium` | the premium a carrier page quotes when it changes: total, term in months, and on GEICO the amount due today and the payments after (`src/premium.js`) |
| `problem_report` | the agent's note from "Report a problem on this page", as typed; values from the loaded intake are replaced where they appear exactly as written there (nothing is replaced when no intake is loaded), so agents should not type client details into it |

Never recorded (apart from what an agent types into a problem report, and the business profile above): client names, numbers, addresses, or anything typed into text boxes; screenshots; keystrokes; other websites. Client names are also redacted from labels and options.

Events wait in `chrome.storage.local` on the agent's computer and are uploaded every minute to the collection server set under **Settings → Advanced, for setup only → Server** (TNI's central server by default). Stored events are removed after acknowledgement and failed uploads retry. The local queue is capped, so a prolonged outage can discard the oldest events. **Export log** works as a fallback. See [learning](docs/learning.md) for the collection and review limits.

### Collection server

```bash
npm run server
```

Plain Node, no dependencies. It listens on `127.0.0.1:8787` and appends events to `server-data/events/YYYY-MM-DD.jsonl`, one file per day. It accepts only known event types and fields, drops agency staff lists from layouts, and ignores duplicates, so retried uploads are safe. Settings: `PORT`, `HOST`, `DATA_DIR`, `RATER_TOKEN`. On this computer (loopback) it needs no token. With `HOST` set to anything else it refuses to start until `RATER_TOKEN` is set (the extension sends it as a Bearer token); also put it behind HTTPS and add the server's address to `host_permissions` in `manifest.json`. `/v1/health` tells anyone the server's version; the event count needs the admin token ([hosting](docs/hosting.md)).

### Weekly review

Every script reads the server folder, exported logs, or both. `npm run review` runs them all and adds what the AI assistant did and the agents' problem reports, in one Markdown file (`reviews/review-<date>.md`, covering what's new since the last review):

```bash
npm run review    # everything below, plus AI accept/reject per question and problem reports
npm run learn     # rule suggestions: standard answers, per-state answers, new intake mappings, rules agents keep correcting
npm run layouts   # carrier page layouts per state/product -> captures/<carrier>/generated/
npm run transitions  # when follow-up questions show, answers not seen yet, what changed after an answer -> reviews/
npm run captures  # manual captures in layouts/, per scenario in order, with what changed between them -> reviews/
npm run summary   # intake problems, corrections, failures, time per page
npm run signals   # builds that logged the period, how far quotes got, what was left and why, what held Continue, problem reports with their build -> reviews/
npm run ledger    # the open weekly-review issue's items: which builds carry each fix, verified / recurred / not exercised, weekly numbers vs. last -> reviews/
node scripts/find-intake.mjs <folder of intake PDFs> server-data   # which intake a session used
```

`signals` and `ledger` aren't part of `npm run review`; the weekly review reads all three (see the `weekly-review` and `apply-review-fixes` skills in `.claude/skills/`). `learn` prints rule lines ready to paste into `src/carriers/<carrier>.js`. **Review each one**: a consistent answer isn't always a correct one. Generated layouts are git-ignored; review them before committing any.

To measure a rule change on recorded quotes before release, replay them through the rules, given a folder with their intake PDFs (matched by fingerprint, never copied). It isn't part of `npm run review`:

```bash
npm run benchmark -- --intakes <folder of intake PDFs> --save reviews/benchmark-main.json   # on main
npm run benchmark -- --intakes <folder of intake PDFs> --against reviews/benchmark-main.json  # on the branch
```

`reviews/benchmark-<date>.md` shows where today's rules agree with what agents left, differ from it, or leave it to the agent, and what changed since the saved run. Agreement with past agents isn't proof of a correct answer; see [learning](docs/learning.md).

TNI's answer key is what a reviewer at TNI decided is right for a set of recorded quotes. The intake PDFs go in `layouts/intakes/` and the key in `layouts/answer-key/`, both ignored: they hold client answers.

```bash
npm run key:sheet -- --intakes layouts/intakes [--key layouts/answer-key/key.json]   # review page -> layouts/answer-key/sheet-<date>.html; save key.json there
npm run benchmark -- --intakes layouts/intakes --key layouts/answer-key/key.json    # adds "Against TNI's answer key": right, wrong, missed, invented (all, and the reviewer's decided answers)
```

When `layouts/answer-key/key.json` exists, `npm run signals` adds the key's score to the weekly numbers.

### Replay test pages

```bash
npm run replay
```

Open `http://localhost:8792/test/replay/`. It rebuilds a carrier's pages from any layout file (a fixture in `test/fixtures/progressive/`, a bake-off course, or one from `npm run layouts`) as working ExtJS pages with Progressive-style ids and server round-trips, then runs the real fill engine. **Fill every page** gives a coverage table: questions per page, how many were filled, what failed, and which have no rule yet. ### Replay regression run (before every release)

```bash
npm run e2e              # every recorded layout (state/product), real fill engine, real browser
npm run e2e -- --update  # accept the current results as the baseline
```

Fills every layout (bake-off course, captures, and the per-state layouts from `npm run layouts`) on the replay page in Playwright's Chromium and compares with `test/e2e-baseline.json`: fewer answers filled, a new failure, or Continue clicked with questions still open fails the run. Report: `reviews/e2e-<date>.md`. One-time setup: `npx playwright install chromium`. The replay page doesn't imitate Progressive's address suggestions, so those stay "failed" there.

### GEICO mock (before every GEICO rule change)

### Synthetic intake variations and AI controls

```bash
npm run test:intakes -- --workers 6
npm run test:intakes -- --carrier amwins --cases 03,09,69,71,97
npm run test:intakes -- --carrier progressive --lookup-check --cases 51,73,74,75,76,77,78,79,80,81,82
npm run package
npm run mock:luna
```

The intake runner reads the actual PDFs in `dist/synthetic-intakes` (or `--pool <folder>`), checks retained answers against the pool manifest, and writes JSON reports and screenshots under a temporary output folder (`--out <folder>` overrides it). The pool stays outside source control. VIN/DOT responses come from its lookup fixtures; no real carrier lookups are made. The mock's exact GVW of 9,000 is a synthetic decoder response, not a weight inferred from a real VIN.

AmWINS exercises the five application steps, including repeated drivers/vehicles and save/reload. A review stop is recorded before the runner continues to inspect later pages; it is not counted as automatic progress. FAO rebuilds captured pages individually. It does **not** establish full quote navigation, backend acceptance, or real lookup reliability. Missing questions and truncated business-type search results are reported as unsupported, alongside existing replay failures such as address autocomplete. Passing the selected assertions is not complete carrier coverage.

The AI runner uses the packaged extension with controlled Luna responses. It checks suggestion acceptance, approval before Continue, preservation of manual edits, and response reuse. It blocks live AI requests and central uploads; it does not measure Luna's live accuracy or latency. Suggestions are cached per intake and active driver/vehicle, and late responses after a context change are discarded.
